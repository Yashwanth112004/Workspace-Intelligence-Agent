# 🧠 WIA Workspace Knowledge Model

The WIA Workspace Knowledge Model defines the relational and semantic structure of a software repository, enabling fine-grained code understanding, graph traversals, and deterministic architectural analysis.

---

## 🏛️ Domain Entities

| Entity Type | Description | Key Attributes |
|---|---|---|
| **`Repository`** | Top-level project container | `id`, `name`, `source_type`, `source_path`, `total_files`, `total_loc`, `tech_stack` |
| **`Directory`** | Filesystem folder / package hierarchy | `id`, `name`, `file_path`, `parent_path`, `depth` |
| **`File`** | Source code or configuration module | `id`, `name`, `file_path`, `language`, `loc`, `size_bytes`, `hash` |
| **`Class`** | Object-oriented class or interface | `id`, `name`, `qualified_name`, `file_path`, `start_line`, `end_line`, `signature`, `docstring` |
| **`Function`** | Standalone function or class method | `id`, `name`, `signature`, `parameters`, `calls`, `return_type`, `docstring`, `start_line` |
| **`Endpoint`** | REST API route definition | `method`, `path`, `framework`, `file_path`, `line` |
| **`Test`** | Unit or integration test case | `name`, `file_path`, `line`, `target_symbol` |
| **`Summary`** | 5-level hierarchical summary object | `level`, `target_path`, `summary_text`, `key_components`, `dependencies` |

## 🛡️ Provenance Tracking

Every entity and relationship in WIA tracks its provenance type:
- **`DETERMINISTIC_FACT`**: Extracted directly via AST parser, import analyzer, or compiler visitor.
- **`LLM_SUMMARY`**: Generated by bottom-up hierarchical summarizer synthesizing deterministic source facts.
- **`LLM_INFERENCE`**: High-level semantic synthesis or natural-language reasoning.
- **`USER_INPUT`**: Manual user configurations or query annotations.
